Get started How it works
QuickExample.java
// one dependency — any model, the best available runtime
CortexJ platform = CortexJ.builder().build();

try (ModelHandle model = platform.models().load(ModelReference.of("Qwen/Qwen3-8B"))) {
    GenerationResponse response = model
            .capability(TextGenerationCapability.class)
            .generate(GenerationRequest.prompt("Explain CQRS"));
    System.out.println(response.text());
}

What it's for

Stop hand-wiring model bindings

CortexJ is an AI runtime orchestration and model portability platform for the JVM. You write against one API — the platform decides where the model lives, which runtime serves it, and what to do when hardware or policy says no.

Model portability

One API for any compatible model — local, Hugging Face or plain HTTP repositories. Immutable revisions: what you resolved is what runs.

Runtime orchestration

The execution planner picks the best available runtime for each model and machine — deterministic scoring, hard constraints, fallback chains.

Java 8 → 25

Starters for every LTS line, identical business code. A starter built for a newer JVM fails fast with the exact remediation.

Explainable decisions

Every plan reports why: hard constraints considered, scores, memory estimates. No mystery paths, no provider-order luck.

How it works

Plan first. Execute second. Explain always.

Runtimes & integrations

Pluggable everything

Runtimes and repositories are plugins discovered via ServiceLoader. The planner decides from descriptors and policies, never from provider order — and adapters slot CortexJ into the frameworks you already use.

Who it's for

Built for JVM teams — legacy to bleeding edge

The same business code runs from Java 8 to Java 25; platform modules pick up what each JVM offers, from fixed thread pools to virtual threads.

Java teams adding AI

Run capable local models inside your JVM stack. One Maven dependency, no Python sidecar, no hand-rolled bindings.

Enterprise & air-gapped

Pinned model lockfiles, verified air-gap bundles, offline re-resolution. Reproducible deployments by construction.

Legacy Java 8–11 stacks

Bring modern AI features to old applications — the same code that runs on Java 25 compiles for Java 8.

Runtime & repository authors

A public SPI, declarative policies and a technology compatibility kit for your provider.

Quick start

One starter, matching your JVM

Add the BOM, add the starter for your JVM line, load a model. The starter validates the JVM at bootstrap — a mismatch fails fast with an actionable diagnostic.

pom.xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>io.cortexj</groupId>
            <artifactId>cortexj-bom</artifactId>
            <version>0.1.0-SNAPSHOT</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependency>
    <groupId>io.cortexj</groupId>
    <artifactId>cortexj-starter-java21</artifactId>
</dependency>
cortexj-starter-java8 cortexj-starter-java11 cortexj-starter-java17 cortexj-starter-java21 cortexj-starter-java25

The business code is identical across all five starters — pick once, never think about it again.
